## Decisions
1. **One file, two readers.** research/preregistration.md is prose for people and one fenced JSON block for the
   gate, as FROZEN.md is. The block binds; a test checks the cell table in the prose against it. The commit that
   last changed the file is the pre-registration commit.
2. **What a cell fixes.** Its scenario file and content hash, its master seed, N, phase (`instrument` or
   `new-evidence`), evidence class (control, replication of one of the three published results, or new
   evidence), and a prediction per invariant: one value (firm), several (one of them in every trial), `*` for
   every invariant not named, or `NOT_EXERCISED`. VIOLATION is never predicted: the checker never writes it.
   Honestly unknown cells say so; their status is `recorded`, not `differs`.
3. **The frozen checker is pinned twice:** by T-10's `checker_sha256` and by the sha256 of FROZEN.md's bytes,
   which also covers the clause registry, effect models, and landmark tables.
4. **The gate** (`authorize_batch`, called by the runner before doctor) refuses unless the checkout is clean; the
   pre-registration is final, committed, and an ancestor of HEAD; the checker is FROZEN, verifies against
   FROZEN.md (T-10's `freeze.verify_checker` with the clause registry's hash), and is the pre-registered one;
   the freeze commit is an ancestor of the pre-registration commit; the scenario's hash, cell, and master seed
   are pre-registered; N is the cell's N; the landmark table verifies; and, for a new-evidence cell, every
   instrument cell came out as predicted. It names every failed condition at once.
   `confirm_environment` runs after doctor: the manifest holds the pre-registered environment, names the
   authorized commit, and is clean.
5. **T-07 and T-10 are reached through adapters** that import them lazily, so this lane merges on main without
   them and without touching `checker/` or `orchestrator/`. Without them the gate refuses ("not in this
   checkout"). Reading a scenario's landmark table is not wired yet (it depends on how T-09 and T-10 carry it),
   so the default adapter refuses that step: no batch can be authorized until it is.
6. **Proof from git, not from the batch.** `verify` checks the run commit against the manifest, ancestry
   (freeze before pre-registration before run), that the pre-registration did not change before the run, every
   hash, exactly N trials, the environment, and each trial's checker.json (frozen checker hash, registry,
   landmark table, FROZEN state, authorized for new evidence).
7. **cells.json, not summary.json.** T-07's runner already writes a summary.json of trial validity in each raw
   batch; the cell statistics go in cells.json (agreed with the T-07 lane).
8. **Pooling fails closed.** Every manifest field is material except `generated_at`, `git_dirty`, and
   `sink_clock_offset_ns`. Batches pool only with the same pre-registration commit, checker, freeze, and
   scenario, and no material difference a recorded compatibility rule (field, both values, reason) does not
   cover. Otherwise each set is its own group, and the cell names the differing fields. Aggregation refuses
   outright if any batch fails verification.
9. **Counting.** INVALID trials count toward the group's INVALID share only; above 2% the group is excluded. In
   other trials an invariant is its outcome, `NOT_EXERCISED` (listed in checker.json, or no result.json at all),
   or `NOT_EVALUATED`. n counts exercised trials; k counts anomaly outcomes (EXPECTED, GAP, VIOLATION_CANDIDATE,
   VIOLATION). Status per invariant: `escalate` on any VIOLATION_CANDIDATE, `unstable` when a deterministic
   cell's trials disagree, then `as-predicted`, `differs`, or `recorded`.
10. **The draft's cells** follow the methodology I approved on 2026-10-09: C1 for nine workload and durability
    variants and C3 for three workloads at N = 50 (the discovery form of the fault-free controls); C2 (K2), the
    misuse controls K5 and K5-reject, and the replications K1a (#8039), K3 (#8796), K4 (#8764) as the
    instrument; then K1b, N1 to N12, N12b, A1 to A4, and E1 at N = 20 as new evidence. A describes clause never
    supports PASS; K1b, N4, A2, and A3 predict I2 under LG-PW-CRASH once LG-PW is split; and a heal after a held
    response is triggered by a fixed delay, never by the read-only probe.

## Integration contracts (agreed 2026-10-10)
- T-07: `crashcourt run` calls `authorize_batch(source, trials, root)` before doctor for any pre-registered batch,
  writes the authorization into the batch as authorization.json, and calls `confirm(authorization, manifest, root)`
  after doctor, refusing the batch on any problem.
  Scenario = one cell; `scenario_sha256(load_scenario(path))`; trial seed = sha256 of the JSON array
  `[master, cell, trial]`, with trials numbered 1 to N (`<cell>/trial-0000n/`). Every scenario hash changes when
  T-09 extends the model. T-07 wires the gate once it is on main.
- T-10: FROZEN.md at src/crashcourt/checker/FROZEN.md; `freeze.verify_checker(text, registry_sha256)` for the
  checker and `freeze.verify_trial(text, registry_sha256, table)` for a cell's landmark table; checker.json per
  trial; a trial with no exercised invariant has only checker.json.
