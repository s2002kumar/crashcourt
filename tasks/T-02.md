## Decisions
1. **LG-DE-RERUN's source moved.** The spec cited the Durable Execution page. Upstream removed it on 2026-05-27
   (langchain-ai/docs#3979, commit 2a8ace1db7, "remove LangGraph Durable Execution docs page"), and its URL now
   redirects (308) to Persistence. The same guidance now lives in the Graph API page's "Re-execution and idempotency"
   section, which the clause cites, and in the Functional API page's "Idempotency" section, which the clause notes
   quote ("may run again"). Polarity and meaning are unchanged, and the paraphrase follows the new wording. I chose the
   Graph API page because V1 workloads are graphs of nodes, not functional-API tasks.
2. **`quotes` field.** The card asks for the interrupts clause "captured exactly". Every clause now carries one or more
   verbatim sentences as rendered (markup dropped). `--refetch` checks each quote against the live page. The page hash
   drifts on any edit anywhere on a page, but a missing quote means the cited wording itself changed. The quotes are a
   few sentences each, not copies of pages.
3. **`snapshot_url` field.** Docs pages are hashed through their Markdown source (`<page>.md`), which returned
   byte-identical content on repeated fetches; the rendered HTML carries build-specific markup. LG-OWN-8796 hashes
   the proposal's README in bharatnpti/langgraph-write-ownership on `main` (identical to commit 9cfadc5), so a refetch
   shows when the proposal changes; the GitHub issue page itself changes with every comment.
4. **Version scopes are the pinned minor lines** (`langgraph >=1.2,<1.3`, `langgraph-checkpoint >=4.2,<4.3`), not the
   version a feature first appeared in. I read today's docs against the pinned release, so a version bump has to
   re-read the clauses before verdicts may cite them again. LG-OWN-8796 is scoped to the conformance release its patch
   targets (0.0.2) and notes that it is in no release.
5. **Paraphrases stay at or below the docs' strength, and my own readings are in `notes`, marked as mine.** Three
   readings need your review. LG-DUR-SYNC: "written" is read as "the saver's put returned". LG-PW: the docs describe a
   node failing; applying it to a process crash (I2, I9) is an interpretation. LG-INT-RERUN: double and conflicting
   resumes have no clause (GAP).
6. **Refetch never fails the build.** Validation errors exit 1; drift, missing quotes, and unreachable sources are
   reported with exit 0, as the card says. Drift is a prompt to re-read a source.

## Candidate clauses found, not added
The card fixes the nine clauses, so these are proposed on the issue rather than added:
- Interrupts, "Handling multiple interrupts": resume values are matched to interrupt calls strictly by index (I8, F07, F08).
- Fault tolerance, "Resume-safe failures": failure provenance is checkpointed, so an error handler sees the same
  NodeError after a crash (langgraph >= 1.2).
- Fault tolerance, "Graceful shutdown": a drained run saves a resumable checkpoint (F15 in V1.5).
- Checkpointers, "Replay": interrupts are always re-triggered during replay.
