## What the checker does

1. **Engine and result model.** `check_trial(artifacts, registry, registry_sha256)` returns schema v1's
   `ResultRecord` and `checker.json`. Output bytes are canonical: two runs, the histories in another order,
   the snapshot's rows in another order, or every `mono_ns` scrambled give the same bytes. `load_trial` reads
   a trial directory (T-07's layout, the histories its trial.json lists, plus `ledger.json`, `snapshot.json`,
   `sink-health.json`) and `write_outputs` writes `result.json` and `checker.json` beside it; a file that is
   absent stays absent, and the trial is INVALID.
2. **Predicates separate from classification.** Layer A returns ANOMALY, NO_ANOMALY, or NOT_EXERCISED with
   evidence pointers and named witnesses; Layer B reads only those.
3. **Unexercised invariants are omitted**, listed in `checker.json` with the missing witness. With nothing
   exercised there is no `result.json`.
4. **Fault not fired is INVALID.** Every arm has exactly one `fp.hit` with the declared action (trigger 10);
   every hit sits at its declared landmark (11); every declared fault shows its 3.6 symptoms (12).
5. **I3 is a harness alarm**: INVALID trigger 15, never an outcome (decision 4; AM5).
6. **Clause polarity from the registry, grades from the mapping.** `classify.py` takes polarity,
   `applies_to`, and the version scope from the registry at classification time.
7. **Describes clauses never carry PASS** (decision 1), checked by the property test.
8. **EXPECTED only with every condition witnessed.**
9. **VIOLATION_CANDIDATE requirements**: a carrying guarantee in scope that forbids the anomaly, no permission
   witnessed, an undisclaimed thread, verified faults, no harness-originated event on the thread. The checker
   never writes VIOLATION (static test).
10. **Synthetic tests** for every invariant on W1 (approve, reject, misuse), W5, a forced fork, kills before
    and after a node's end, LG-PW-EXC's exception case, a SIGSTOP fork, a loss before the first checkpoint,
    network and database faults, a double resume.
11. **Mutation tests.** AM1-AM10 give the named outcomes; each predicate has a mutant that makes it fail.
12. **Freeze plumbing.** `freeze.compute` hashes every checker file, the registry, each effect model, and
    each landmark table; `render`, `parse`, `verify_checker` (the batch gate's check), `verify_trial` (per
    trial, with its landmark table), and `verify_scenario` (a cell's `landmarks: <name>` key against the frozen
    tables). `test_the_frozen_record_matches_the_checker` is mandatory in both states: before the freeze
    `FROZEN.md` must not exist; after it, it must match the checker files, effect models, registry, and every
    repository landmark table byte for byte, and every table must be audited.

## My rules and rulings of 2026-10-10

- **client.fail is observational.** It says the client received an error, never that the run changed
  nothing; the oracle decides (`test_client_fail_is_observational`).
- **What a controlled fault leaves is evaluated, not invalidated.** A killed worker's saver call still in
  flight may commit after the kill: if the two snapshots differ only by rows such calls wrote, the second is
  evaluated and the difference noted in `checker.json`; any other difference is INVALID (trigger 7).
- **INVALID trigger 16, "uncontrolled trial"**: the orchestrator marked the trial invalid; a worker ended with
  a signal or status no declared fault explains; an orchestrator fault struck a worker no declared barrier held
  (artifact mutants are exempt from this last rule only).
- **INVALID triggers 1 and 3**: mismatched provenance; missing causal evidence.
- **Running at a stop**: `node.start` occurred and its matching `node.end` had not occurred before the stop. A
  node whose `node.end` occurred while its task's writes were still in flight was not running; pending-write
  semantics own that case. This settles the contradiction I recorded before the audit: at K1a's kill (L-EXW,
  `put_writes.before`) execute has ended, because LangGraph saves a task's writes after the node returns, so
  I4(a) and I7a's permission do not apply and both read GAP, with the reason naming pending-write semantics
  (`test_ruling_a_node_that_had_ended_was_not_running_at_the_stop`). A kill before `node.end` is still
  EXPECTED under LG-DE-RERUN.
- **L-RES** is the `put_writes` carrying the RESUME write for the interrupted task, identified by channel and
  task, not the null task's copy of the Command's value and not the checkpoint put that follows. I8 compares
  against the same write.
- **Landmark tables**: a fault scenario names its table with a top-level `landmarks: <name>` key (names
  `[A-Za-z0-9._-]+`, resolved only inside scenarios/landmarks/); a fault-free scenario needs none.

## Decisions before the freeze

Each default is what the checker does now. Each changes an outcome on a cell, so I decide it before the
freeze.

- **D1 (R4, R5): which invariants LGP-DT's disclaimer and harness-originated events cover.** Default, 1.1 as
  written: on a thread with concurrent writers or two resume invokes after one interrupt, no invariant has
  PASS or a candidate, and a redelivery or a repeated logical op withholds every candidate. A client's retry
  after `client.fail` is a second resume invoke, so the retry cells (N1-N4, N9) are disclaimed throughout. N9
  was built to test durability across a database restart (H8), but it can give only NO_ANOMALY_UNSPECIFIED or
  GAP. In K1a, I1b can PASS, but a missing acknowledged checkpoint would be a withheld GAP: a PASS that could
  not have failed. The alternative is per invariant: both cover only the invariants about what a second run
  does (I2, I4, and the GAP-only I5-I8). The durability invariants (I1a, I1b, I11) state no writer condition,
  and no second run can produce their anomalies: I1a is one process's own order, and no graph run deletes
  saver rows (only the explicit `delete_thread` does, saver `__init__.py:381`, `aio.py:665`). Under it, N9
  and K1a judge durability by PASS or a candidate, and I2 and I4 are unchanged.
- **D2 (R7).** Default (2.3 as written): I4 PASS under LG-PW-EXC whenever there is no duplicate and no crash.
  The alternative is narrower: PASS only where LG-PW-EXC's situation (a node raised) occurred, otherwise
  NO_ANOMALY_UNSPECIFIED. That changes C1's W1-approve I4, N10, and A4 from PASS to NO_ANOMALY_UNSPECIFIED,
  and makes I4 PASS a W2/W3 outcome.
- **D3 (R16).** Default: the most severe outcome wins, so a candidate is never hidden. Alternative: the first
  anomaly's outcome.
