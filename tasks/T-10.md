## What the checker does

1. **Engine and result model.** `check_trial(artifacts, registry, registry_sha256)` returns schema v1's
   `ResultRecord` and `checker.json`. Output bytes are canonical: two runs, the histories in another order,
   or every `mono_ns` scrambled give the same bytes. `load_trial` reads a trial directory (T-07's layout plus
   `ledger.json`, `snapshot.json`, `sink-health.json`) and `write_outputs` writes `result.json` and
   `checker.json` beside it; a file that is absent stays absent, and the trial is INVALID.
2. **Predicates separate from classification.** Layer A returns ANOMALY, NO_ANOMALY, or NOT_EXERCISED with
   evidence pointers and named witnesses; Layer B reads only those.
3. **Unexercised invariants are omitted**, listed in `checker.json` with the missing witness. With nothing
   exercised there is no `result.json`.
4. **Fault not fired is INVALID.** Every arm has exactly one `fp.hit` with the declared action (trigger 10);
   every hit sits at its declared landmark (11); every declared fault shows its 3.6 symptoms (12).
5. **I3 is a harness alarm**: INVALID trigger 15, never an outcome (decision 4; AM5).
6. **Clause polarity from the registry, grades from the mapping.** `classify.py` takes polarity,
   `applies_to`, and the version scope from the registry at classification time.
7. **Describes clauses never carry PASS** (decision 1), checked by the property test.
8. **EXPECTED only with every condition witnessed.**
9. **VIOLATION_CANDIDATE requirements**: a carrying guarantee in scope that forbids the anomaly, no permission
   witnessed, an undisclaimed thread, verified faults, no harness-originated event on the thread. The checker
   never writes VIOLATION (static test).
10. **Synthetic tests** for every invariant on W1 (approve, reject, misuse), W5, a forced fork, kills,
    LG-PW's exception case, a SIGSTOP fork, a loss before the first checkpoint, network and database faults,
    a double resume.
11. **Mutation tests.** AM1-AM10 give the named outcomes; each predicate has a mutant that makes it fail.
12. **Freeze plumbing.** `freeze.compute` hashes every checker file, the registry, each effect model, and
    each landmark table; `render`, `parse`, `verify_checker` (the batch gate's check), and `verify_trial` (per
    trial, with its landmark table). `test_the_frozen_record_matches_the_checker` is mandatory in both states:
    before the freeze `FROZEN.md` must not exist; after it, it must match the checker files, effect models,
    registry, and every repository landmark table byte for byte, and every table must be audited.

## My rules of 2026-10-10

- **client.fail is observational.** It says the client received an error, never that the run changed
  nothing; the oracle decides. A failed op's acknowledged checkpoints and effects are judged as recorded
  (`test_client_fail_is_observational`).
- **What a controlled fault leaves is evaluated, not invalidated.** A killed worker's saver call still in
  flight (a call with no return or raise, in a worker that exited by a signal) may commit after the kill: if
  the two snapshots differ only by rows such calls wrote, the second is evaluated and the difference noted in
  `checker.json`; any other difference is INVALID (trigger 7).
- **INVALID (new trigger 16, "uncontrolled trial")**: the orchestrator marked the trial invalid (T-07's
  trial.json: a protocol violation, a run a timer ordered, an unexplained exit); a worker ended with a signal
  or status no declared fault explains; an orchestrator fault struck a worker no declared barrier held (a kill
  whose worker's history does not end at an unreleased declared pause, or a database fault with no declared
  pause held across it). Artifact mutants, which plant stops on purpose, are exempt from the last rule only.
- **INVALID (triggers 1 and 3)**: mismatched provenance (synthetic and mutant trials are fixtures, controls
  and replications are runs; every event of this trial; ledger rows on its threads; a run's threads scoped
  `<batch>/<cell>/<trial>/`; a run needs the orchestrator's trial record); missing causal evidence (a worker
  acting on an op never dispatched to it, an `fp.action` naming no earlier hit, a response to a request never
  made, a `node.end` closing no run).

## Contradiction found (decide before the freeze)

**"Running at a stop" (2.0) cannot witness I4(a), so K1a / C11-8039 cannot give its predicted EXPECTED, and
no controlled V1 schedule can reach LG-DE-RERUN at all.** 2.0: "Running at a stop: a node with `node.start`
and no `node.end` in that process before the stop's seq." I4(a) and I7a's permission need "a stop while the
producing node was running". LangGraph writes a task's writes only after its node function returns
(`pregel/_runner.py:574`, `commit`, success branch at `:613`, langgraph 1.2.12), and 4.2 defines L-EXW as
"after `node.end execute`", so at K1a's kill (L-EXW's `put_writes.before`) execute has ended: (a) cannot hold
and the duplicate falls to (e), GAP, where K1a predicts EXPECTED (a) and C11-8039 must match its published
outcome in 19 of 20. More broadly, a controlled stop happens at a failpoint, that is, inside a saver call, and
no W1 or W5 node makes a saver call while it runs; T-07 refuses any other stop. So in V1 the re-run
permission is reachable only by the artifact mutant AM7. Pinned by
`test_checker_readings.py::test_contradiction_running_at_a_stop_and_the_c11_8039_shape`. I implemented 2.0 as
written.

## Found while preparing the landmarks

**L-RES as 4.2 states it ("put_writes ... data.channels includes `__resume__`") matches two calls in every
resume run**: the null task's write of the Command's resume value (`pregel/_io.py:75`) and the interrupted
node's own RESUME list (`types.py:1018`). The integration test confirms both rows on the real saver. 4.2
hypothesizes "occurrence 1"; the generic rule `first_call` would make it the null task's write, but which call
L-RES names is the audit's choice. The draft table keeps 4.2's rule, and the extraction reports the ambiguity.

## Review

A review against the specification found two blockers and four major problems, all fixed with regression
tests (`test_checker_regressions.py`): a network fault that never touched its call verified (now R20); I1a
paired a lost-ack put with a later run, a false candidate (pairs are now within one run); trigger 6 was too
loose, any non-zero exit was a stop, and undeclared faults fed the stop witnesses (R21-R23); I7a gave EXPECTED
on a disclaimed thread (R24); a frozen trial without the frozen landmark table raised (R25); and the SIGSTOP
silence check cannot fire with schema v1's edges (R19). R7 had departed from 2.3; it now follows the text.
