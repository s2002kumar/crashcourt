## Review fixes
The review of ef74767 (2026-09-28) asked for six changes. Each is fixed in the commits after ef74767:

1. **Python pinned.** .python-version is 3.12.13, `python-preference = "only-managed"` keeps uv from using a system
   interpreter, doctor fails when the running Python differs from .python-version, and C7 compares the full version
   and the implementation. The run at ef74767 used the runner's /usr/bin/python3.12 (3.12.3) and passed only because
   C7 compared 3.12 with 3.12.
2. **Every LangGraph and psycopg distribution recorded.** The manifest adds langgraph-prebuilt, langgraph-sdk, and
   psycopg-binary; a test fails if uv.lock gains a langgraph* or psycopg* distribution the manifest does not record.
   It also records psycopg's implementation, its wheel, and the libpq it loaded and was built against, and doctor
   fails unless psycopg can use its bounded cancel (decision 9).
3. **Kernel and runner.** `docker_kernel` records the Docker engine's kernel, the one Postgres and Toxiproxy run on;
   on this machine that is the WSL2 VM's 6.6.87.2, while `os_release` is the host's "11". `runner` records `local`,
   `github-hosted`, or `self-hosted`; another CI system is `unknown`. Validation rejects an empty kernel field or one
   that does not start with a version number (such as the host's "11"), and any other runner value.
4. **Running images checked.** doctor now compares each running container's image ID with the ID the pinned ref
   resolves to on the same engine, fails on a mismatch, and records the IDs. `docker compose config` still supplies
   the pinned refs. On the real engine, a container recreated from another image under the same project fails the
   check (research/evidence/t-01/stale-container.txt).
5. **CI tests the PR head.** Both jobs check out `github.event.pull_request.head.sha` (or `github.sha` on a push),
   and the doctor job fails if the manifest's git_sha is not that commit. At ef74767 the manifest named 03e8f80, the
   merge commit GitHub creates for the pull request.
6. **Small ones.** The head CI run is linked above; the psycopg-pool reason is corrected and C11 is described as
   planned (decision 1); step 1 of #1 and of the card copy below now read as plain task notes.

A second, independent review of those fixes found more, fixed in the same PR:
- psycopg uses its bounded cancel only when libpq is 17 or newer both at runtime and at build time
  (`capabilities.has_cancel_safe()`); otherwise `cancel_safe()` falls back to a blocking `cancel()`. My first check
  read only the runtime version. doctor now asks psycopg directly, and the manifest records the build version.
- Comparing libpq by major version alone let two runs on the same platform differ silently. The comparison is now
  per wheel (decision 9).
- `--compare` against a manifest of the earlier shape crashed with a traceback; it now names the missing fields and
  exits 2, and a unit test fails whenever the committed reference manifest is incomplete or was written from a dirty
  tree.
- With the Docker daemon down, every Docker probe waited out its own 60-second timeout. doctor now skips them. Probe
  errors and unreadable compose output are failed checks rather than crashes; a scaled service has every container
  checked; uv itself is pinned in pyproject.toml (decision 6); and the CI check also requires a clean tree.
- Left for later, with reasons: the SQLite library version belongs in the manifest when the SQLite target arrives
  (T-12); the host kernel on Windows does not matter once T-07 keeps runs on Linux.

A third review, of that second round, found five more, fixed in b503e4b:
- Across platform wheels only the runtime libpq major was compared, and the note said "majors match" without
  checking. The build-time major is compared too, and the note says which majors differ.
- A reference manifest with empty wheel tags switched on the cross-platform allowance for two runs on one platform.
  Both sides now need tags.
- `--compare` did not check field types or the reference's own validity, and a missing file raised. The reference
  must now parse with the right types and pass validation before anything is compared.
- Subprocess output was decoded with the Windows codepage, so a non-UTF-8 byte could crash doctor; it is decoded as
  UTF-8 with replacement.
- An unreadable uv.lock, a compose config without services, or a container that cannot be inspected could crash
  doctor or drop out of the comparison; each now fails a check. Azure Pipelines and similar CI systems are recorded
  as `unknown`.
- Left for later: per-container health for a scaled service (fixed host ports keep each service at one container),
  and pure JSON on stdout when `--json` and `--compare` are combined (also true before this PR).

## Decisions
1. **psycopg 3.3.6 instead of 3.3.4, and psycopg-pool pinned at 3.3.3.** The 3.3.4 pin came from the environment in an
   upstream issue report, not from a choice. Every LangGraph distribution is pinned to its newest release, and the
   driver now follows the same rule. 3.3.6 also stops an interrupted query from waiting forever on an unresponsive
   server (psycopg #1371), which is the situation the network-fault cells create; that fix needs libpq 17 or newer,
   so doctor checks it. langgraph-checkpoint-postgres 3.1.2 already requires psycopg-pool, without a version bound,
   and uv.lock pins it either way; the explicit pin keeps its version next to the other pins in pyproject.toml, so a
   lock upgrade cannot move it unnoticed. Main alternative: keep 3.3.4 to match the #8796 repro environment. That
   environment already differs (langgraph 1.2.11), and C11 is planned to replicate #8796 on our pins (T-11), so
   matching the driver alone would buy little.
2. **Toxiproxy 2.12.0.** 2.9.0 was not the newest release. 2.10.0 through 2.12.0 update Go and dependencies and fix
   proxy restarts on hostname listen addresses; no toxic changed behavior.
3. **`postgres:18.6` instead of `postgres:18`.** The digest pins the image either way. With an explicit minor, the tag
   and the digest say the same thing, and re-running the pin script does not silently move to a new minor.
4. **Postgres published on 127.0.0.1:55432.** My machine runs a native PostgreSQL 18 service on 0.0.0.0:5432, as
   many developer machines do. Binding the lab to 5432 would collide with it, or silently send `doctor` to the wrong
   server. The DSN default moved with it; `CRASHCOURT_PG_DSN` still overrides it.
5. **LF line endings everywhere (.gitattributes).** The manifest records the sha256 of uv.lock, so a CRLF checkout
   (Git for Windows defaults to `core.autocrlf=true`) would change the hash and fail C7. For the same reason,
   `pin_images.py` and `doctor` now write bytes: `Path.write_text` produced CRLF on Windows. Tests cover both.
6. **uv pinned to 0.12.1**, the version that wrote uv.lock, so a newer uv cannot rewrite the lock under `--locked`:
   in CI by setup-uv, and everywhere by `required-version` in pyproject.toml, since the uv release also decides which
   build of Python 3.12.13 gets installed. Dev tools (pytest, hypothesis, ruff, pyright) keep lower bounds in
   pyproject.toml and are pinned by the lockfile.
7. **Strict pyright fixes without suppressions.** `isinstance(x, dict)` on an `Any` value narrows to
   `dict[Unknown, Unknown]`; parsed JSON and TOML objects are now cast to `dict[str, object]` instead of carrying
   per-line ignores.
8. **Python 3.12.13 from uv only.** Pinning the patch release in .python-version is not enough on its own: uv
   accepts a system interpreter that satisfies the request, and a runner image can change its system Python. With
   `only-managed`, the laptop and CI run the same python-build-standalone release of 3.12.13. Main alternative:
   setup-uv's `python-version` input in CI only; it would leave local runs free to use a system Python.
9. **libpq compared per platform wheel.** psycopg-binary 3.3.6 bundles libpq 18.4 in its Windows wheel and 18.6 in
   its Linux wheel (measured with `psycopg.pq.version()`), so identical pins load different libpq builds on different
   platforms. The manifest records the wheel tags, the runtime libpq, and the build-time libpq. The comparison
   requires the full versions to match, except when both runs used the binary implementation from different
   wheels: then the major must match and the minor difference is printed with every comparison, never hidden.
   doctor fails unless psycopg reports `cancel_safe()` as available. Main alternative: always compare the full
   version, which fails every comparison between this Windows laptop and a Linux runner unless the local reference
   manifest is produced on Linux. I decided against setting up WSL2 just to manufacture an identical reference for
   T-01. Canonical benchmark and publication runs will use one Linux benchmark environment, so publishable batches
   are homogeneous.
10. **Running image IDs recorded, not compared across machines.** An image ID depends on the engine's image store:
    on Docker Desktop here (containerd store) it equals the registry digest pinned in compose.yaml. On the
    ubuntu-24.04 runner (classic store) it is the image config digest: the same postgres image is
    sha256:662db3da… there and sha256:5a5a84b1… here.
    doctor compares a container's ID only with the ID the pinned ref has on the same engine, which is the question
    that matters: is the running container the pinned image.
11. **Both CI jobs test the PR head.** Alternative: keep the merge commit in the unit job to catch conflicts with
    main. It lost because the two jobs would then test different trees, and a stacked branch is rebased before it
    merges anyway.
12. **Manifest schema stays at version 1.** Manifests of the earlier shape exist only in this branch's history and
    in CI artifacts; after the squash merge, main never contains one, and `Manifest.from_json` rejects one by naming
    its missing fields instead of misreading it. v1 is frozen when T-04 merges; when T-04 rebases onto this branch,
    its Pydantic model and schemas/v1/manifest.json gain the new fields.
13. **What `--compare` checks, and what T-13 must enforce.** `--compare` answers whether the pins reproduce the
    same environment on two machines, which is the T-01 evidence. It is not the rule for combining batch results.
    That rule belongs to T-13, which owns aggregation, and it must fail closed: every batch carries its environment
    and runner fingerprint; batches from different runner types, platforms, or materially incompatible dependency or
    runtime fingerprints are never pooled silently; heterogeneous batches are reported separately, or combined only
    through an explicit compatibility rule recorded in the artifact; and no statistic or page presents heterogeneous
    runs as one population by default. T-01's part is to record the fingerprint: runner, OS, machine, Docker kernel,
    Python version and implementation, lockfile hash, package versions, psycopg implementation and wheel, libpq
    runtime and build versions, image digests, and running image IDs.
