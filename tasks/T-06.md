# T-06 · Failpoint saver and disarmed transparency

`get_tuple`, `list`; before and after) and actions (none, pause, exit, signal self). Every hit is logged before its
action. Depends on T-04. Learning checkpoint S7.

## Decisions
1. **Capabilities are mirrored per inner type.**
   - The conformance suite detects extended capabilities by checking which methods `type(saver)` overrides.
   - `wrap()` builds (and caches) a subclass that forwards exactly the extended methods the inner type overrides, so
     the wrapper can never claim, or hide, a capability.
   - Everything else a saver provides is forwarded: `serde`, `config_specs`, `get_next_version` (the Postgres saver
     uses its own version format), delta-channel history, `delete_thread`, and `with_allowlist`.
2. **Failpoints do not cover delta-channel reads or deletes.** Those forward directly to the inner saver, so its own
   reads bypass failpoints and behave exactly as unwrapped. The card's four operations are the failpoint surface;
   SQL-level points are V1.5.
3. **Event order.** `saver.<op>.call`, then `<op>.before`, the inner call, `<op>.after`, then `.return`, or `.raise`
   with no `after` if the inner call raised. A firing records `fp.hit` before its action and `fp.action` after it,
   which for a pause means after the release. That is the order T-04's barrier edge expects: hit, release, action.
   `list` records completion, or `complete: false` when the caller stops early.
4. **Matching.**
   - An arm fires once, on the nth matching call (`occurrence`, from 1), optionally narrowed by worker, op_id, and
     thread_id.
   - The op_id comes from a context variable the worker sets. LangGraph's background executor and asyncio copy
     contexts, so writes submitted in the background still carry it.
   - When two arms fire on one call, the earliest armed wins.
5. **Safety.**
   - Arming requires a history writer, because every hit is logged.
   - A pause with no barrier raises `FailpointError`, a spec error, so the trial is INVALID.
   - Invalid arms are rejected at construction: an unknown point or action, a signal without a name, or an
     occurrence below 1.
6. **Postgres conformance on a fresh database.** The suite lists checkpoints across all threads, so each capability
   suite runs on a newly created database, dropped afterwards.
7. **Overhead.** On Linux, the wrapper alone adds under 1% to a Postgres `put`; recording two history events adds 11–13%
   at p50. Following C4, I investigated (research/evidence/t-06/README.md):
   - the inner call is unchanged, and the time is spent building the events on cold caches (mostly Pydantic
     validation);
   - deterministic cells are unaffected;
   - I proposed a cheaper emit on the issue as a follow-up.

   The Windows host was too noisy to measure on, so no Windows numbers are recorded.
8. **New C7 reference.** The dev dependency changed uv.lock. research/evidence/t-06/manifest-local.json differs from
   T-04's only in `lockfile_sha256`.
