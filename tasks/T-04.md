## Decisions
1. **The envelope is exactly spec section 9, plus `effect_key`.** The card lists `effect_key` among the identifiers,
   and section 9's identifier table has it, but its example line does not. It sits after `attempt`. Every line carries
   every field, null where it does not apply.
2. **Kinds are exactly the spec's families, 30 in all.** `saver.<method>.{call,return,raise}` covers the four methods
   the failpoint saver names (`put`, `put_writes`, `get_tuple`, `list`); async methods log under the same names. No
   kind was added.
3. **Choices where section 9 is silent:**
   - `status` is `ok`, `fail`, or `info`;
   - `attempt` starts at 1 (LangGraph's `node_attempt` does too);
   - `trial`, `seq`, and `pid` are non-negative;
   - integers are strict (a boolean is not a seq).
4. **Cross-process edges come from `data`, not new envelope fields.** Kinds the merger links must carry what it needs,
   checked when an event is loaded:
   - dispatches name the worker (`data.to`);
   - releases name the paused hit (`data.proc`, `data.hit_seq`);
   - actions name their hit (`data.hit_seq`);
   - sink appends name the worker (`data.worker`);
   - exits name the process (`data.proc`).

   JSON Schema cannot express these rules, and the schema's description says so.
5. **A fifth edge: results.** The merger's first sample showed a `client.ok` placed before the worker had started, which
   is causally allowed when nothing links a result to the work behind it. A worker knows its own last `seq` when it
   sends a result, so `client.ok` and `client.fail` may carry `data.worker` and `data.worker_seq`, and the merger orders
   that worker event first. T-07's control protocol should fill them in.
6. **Two tempting edges are left out because they can be false.**
   - `worker.start` before the worker's first event: a child can log before the parent records the spawn.
   - Every worker event before `client.ok`: background saver writes can finish after the result.
7. **Windows clock.** Windows has no `CLOCK_MONOTONIC`, and `time.monotonic()` there is `GetTickCount64()` with 15.6 ms
   resolution, which made most sample events tie. The writer uses `clock_gettime_ns(CLOCK_MONOTONIC)` wherever it
   exists (Linux, macOS; the spec's clock) and `perf_counter_ns()` (QueryPerformanceCounter, 100 ns, system-wide) on
   Windows.
8. **Durability of a line.** One `os.write` per event on an `O_APPEND` descriptor opened with `O_EXCL`, so a second
   writer cannot share or truncate a file. There is no fsync: the spec protects against a killed process, not a lost
   machine.
9. **The kill test is in the integration tier.** It spawns real processes and takes about 50 s, so it runs in CI's
   Linux job. The `integration` marker's description now says "real OS processes, Docker, or the compose services".
10. **The manifest model is strict now.** It rejects unknown fields and `schema_version` other than 1. Its JSON form is
    unchanged.
11. **`.gitignore` anchored.** The pattern `manifest.json` also matched `schemas/v1/manifest.json`, so CI's first run failed the schema check on a file that was never committed. It is now `/manifest.json`.
12. **New C7 reference.** Adding pydantic changed uv.lock, so CI compares against research/evidence/t-04/manifest-local.json,
    which differs from T-01's only in `lockfile_sha256`.

## Card (issue #4)
Deliverables:
- `src/crashcourt/spec/events.py`: Pydantic schema v1 exactly as spec section 9: envelope fields; kinds client.*,
  dispatch.*, worker.*, node.*, saver.*, fp.*, effect.*, sink.append, fault.*; identifiers batch, cell, trial, op_id,
  logical_op, attempt, effect_key, checkpoint ids, fault_id. **Done.**
- `src/crashcourt/history/writer.py`: one flushed line per event, per-process `seq`, schema-versioned, no buffering.
  **Done.**
- `src/crashcourt/history/merge.py`: causal edges (request and response pairs, barrier releases, `effect.request`
  before `sink.append`); `mono_ns` only breaks ties; deterministic output. **Done.**
- `crashcourt schema export` writes `schemas/v1/*.json`; CI fails if the committed schemas differ from the models.
  **Done.**
- Migrate the T-01 manifest to Pydantic with byte-identical JSON (round-trip tests). **Done.**

Tests: Hypothesis properties (the merge is deterministic, respects `seq` and every declared edge, and is independent
of input order); kill test (SIGKILL a writer subprocess 100 times mid-stream; every complete line parses; at most the
final partial line is lost); schema export is stable. **Done.**

Manual check (mine): `kill -9` a writer in a loop and inspect the file.

Completion gate: schema v1 frozen and exported; tests green; a sample merged history in research/evidence/t-04/.

Do not: add OpenTelemetry; order by wall clock; buffer events in memory; add event kinds beyond the spec without an
issue comment (none added).
