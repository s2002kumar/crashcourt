## Decisions
1. **Capabilities are mirrored per inner type.**
   - The conformance suite detects extended capabilities by checking which methods `type(saver)` overrides.
   - `wrap()` builds (and caches) a subclass that forwards exactly the extended methods the inner type overrides, so
     the wrapper can never claim, or hide, a capability.
   - Everything else a saver provides is forwarded: `serde`, `config_specs`, `get_next_version` (the Postgres saver
     uses its own version format), delta-channel history, `delete_thread`, and `with_allowlist`, which returns the
     wrapper itself when the inner saver returns itself.
2. **Failpoints do not cover delta-channel reads or deletes.** Those forward directly to the inner saver, so its own
   reads bypass failpoints and behave exactly as unwrapped. The card's four operations are the failpoint surface;
   SQL-level points are later work.
3. **Event order.** `saver.<op>.call`, then `<op>.before`, the inner call, `<op>.after`, then `.return`, or `.raise`
   with no `after` if the inner call raised. A firing records `fp.hit`, then `fp.action` just before it acts: for a
   pause, after the release (the order T-04's barrier edge expects: hit, release, action); for an exit or a signal,
   before the process ends. When the caller stops a `list` early, the wrapper closes the inner iterator, so a saver
   holding a cursor releases it, and then records `complete: false`, even if closing fails. A failpoint that
   raises, before or after the inner call, records `saver.<op>.raise`, so every call event has its end;
   `data.stage` says what raised (`before`, `inner`, or `after`), and after `after` the write is already stored.
4. **Matching.**
   - An arm fires once, on the nth matching call (`occurrence`, from 1), optionally narrowed by worker, op_id, and
     thread_id.
   - The op_id comes from a context variable the worker sets. LangGraph's background executor and asyncio copy
     contexts, so writes submitted in the background still carry it.
   - Two arms due on one call is a `FailpointError`. Only one action can run there, so the other arm would never fire
     and the trial would run a different schedule from the one declared. Overlap is checked when it happens rather
     than when arming: two arms with different filters may or may not meet. Both arms are retired, and
     `FailpointRegistry.failed` lists them, with any arm that was due but could not act (no barrier, a signal the
     host cannot send), so a finished trial can tell them from arms that fired.
   - Occurrences are counted at the failpoint, under the registry's lock. With concurrent calls, the nth call to
     reach a failpoint need not be the nth `saver.<op>.call` in the history; the `fp.hit` records the occurrence.
5. **Safety.**
   - Arming requires a history writer, because every hit is logged.
   - A failpoint that cannot be honored (two arms due, a pause with no barrier, a signal the host lacks) writes
     `fp.hit` with status fail and raises `FailpointError`, a spec error, so the trial is INVALID.
   - A signal goes to the calling thread (`pthread_kill`), not the process. LangGraph runs saver calls on its
     background executor's threads, and a signal sent to the process can land on another thread while the call
     goes on: a measurement on Linux saw thousands of loop iterations run after SIGQUIT or SIGABRT that way, and
     none with `pthread_kill`. A real-process test signals from a worker thread and checks the write was never
     stored.
   - Only signals that act at the point: SIGKILL and SIGSTOP, which cannot be caught, and SIGQUIT, SIGABRT, and
     SIGSEGV, which end the process by default. A signal Python handles (SIGINT, or SIGTERM once a worker installs a
     handler) runs its handler later on the main thread, so the action would not happen at the point. A host that
     cannot signal a thread (Windows) fails the hit.
   - Invalid arms are rejected at construction: an unknown point, action, or signal, a signal on an action other than
     `signal`, an exit status on an action other than `exit` or outside 0 to 255, or an occurrence below 1.
6. **C4 wraps as a trial does.** Every wrapped saver in the comparisons records to a history writer with an empty
   failpoint registry, and what it stored is read back through the raw saver. The suite exercises only the async API,
   so a fixed sync script covers the sync methods.
7. **Postgres conformance on a fresh database.** The suite lists checkpoints across all threads, so each capability
   suite runs on a newly created database, dropped afterwards. The sync script does the same.
8. **Overhead.** On Linux, the wrapper alone adds under 1% to a Postgres `put`; recording two history events adds 11–13%
   at p50. Following C4, I investigated (research/evidence/t-06/README.md):
   - the inner call is unchanged, and the time is spent building the events on cold caches (mostly Pydantic
     validation);
   - deterministic cells are unaffected;
   - I proposed a cheaper emit on the issue as a follow-up.

   The measurement wraps without a failpoint registry; an empty one adds a lock and an empty loop per failpoint. The
   Windows host was too noisy to measure on, so no Windows numbers are recorded.
9. **The conformance suite is installed with the harness and recorded in the manifest.** Its version is part of
   C4's evidence, and every langgraph distribution in uv.lock is pinned in the manifest. As a dev dependency, an
   install without the dev group (a worker container, for one) failed doctor and wrote a manifest missing a pinned
   package; it depends only on langgraph-checkpoint, so it is a runtime dependency now.
10. **New C7 reference.** The conformance suite changes uv.lock. research/evidence/t-06/manifest-local.json differs
    from T-04's in `lockfile_sha256` and the conformance suite's version. It was re-recorded at 1a254e9, after the
    rebase onto T-04's final tip, because T-02's final note on LG-PW changed the clause registry's version.

## Review fixes
The review of d28b192 (2026-10-08) asked for five changes and five smaller ones:

1. **Arm collisions** are a `FailpointError` (decision 4), with tests for a collision and for two arms due on different
   calls.
2. **Signal names** are checked when the arm is built, and a pause with no barrier logs a failed `fp.hit` before it
   raises (decision 5).
3. **Conformance runs record.** The Postgres and SQLite runs, and the in-memory one, wrap with a history writer and an
   empty registry; conformance.md is regenerated (decision 6).
4. **Sync coverage.** The graph comparisons read back through the raw saver, and a sync script compares every sync
   method on InMemorySaver, SqliteSaver, and PostgresSaver (decision 6).
5. **Pause position** is tested at all eight points, sync and async.

Smaller: `list` and `alist` close the inner iterator on early exit; `with_allowlist` returns the wrapper when nothing
changed; the `fp.action` wording says it is logged just before the action; the always-true `assert config` is gone;
the record's counts and CI run are current.

Also changed: exit statuses outside 0 to 255 are rejected; a paused test thread is always released, so a failing
assertion cannot leave the interpreter waiting at exit; the conformance suite is pinned in the manifest (decision 9);
the evidence script takes `conformance` to regenerate conformance.md alone.

A second review of those fixes found more, fixed here:
- The close test passed without the fix (reference counting and asyncio's shutdown closed the inner iterators), and
  the pause test could not tell `.before` from `.after` for `get_tuple` and `list`. Both now fail with their fixes
  reverted.
- SIGINT and SIGTERM are no longer accepted (decision 5).
- The dev-only conformance suite broke doctor for installs without the dev group (decision 9).
- A failpoint error left a call event with no end; arms retired by a collision were indistinguishable from fired
  ones; `exit_code` was accepted on other actions (decisions 3 to 5).
- The sync comparisons check that they compared something; the record says which sync methods the script covers and
  in which order `list` closes and records.

A third review found a real gap, fixed here: a self-sent signal went to the process, so on LangGraph's background
threads only SIGKILL acted at the point (decision 5). Also: `.raise` now says which stage raised; arms that could not
act are listed; closing a `list` early records its end even if closing fails; an inner `list` that raises at once is
tested; the record's dependency and image wording. `InProcessBarrier` waits without a timeout, so a test that cancels
a paused coroutine must release it; T-07's barrier is the one trials use.
