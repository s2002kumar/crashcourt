# Evidence explorer: JavaScript budgets

Budgets are set from measurements of the real routes, and CI fails when a route grows past its limit
(`npm run size`). The limits are in `budgets.json`; this file records how they were measured.

## How it is measured

`scripts/measure-bundles.ts` serves the static export, opens each route in Chromium, and records three
numbers per route:

| Number | Meaning |
| --- | --- |
| initial | The JavaScript the exported HTML loads. `nomodule` polyfills are excluded: modern browsers never fetch them. |
| total | Initial plus the route's own lazy chunks, measured with the router's prefetch requests blocked. |
| loaded | Everything fetched once the page settles, including chunks of linked routes that the router fetches ahead of a click. |

Sizes are gzip at level 9 per file, summed (as size-limit computes them), in kB of 1000 bytes. A trailing
`sourceMappingURL` comment is not counted, so a source-mapped build measures the same as a release build.

Library costs come from a build with source maps (`CRASHCOURT_SOURCEMAPS=1`): every generated byte is
traced to its source file, and sources are grouped by npm package. "Own" is the package alone; "with
dependencies" adds every package it depends on that is in the route's bundle, counting shared ones once.
Each figure is the gzip size of those bytes concatenated on their own, which slightly overstates what they
add inside a larger file (gzip shares context), so read them as upper bounds.

## Measurements

Release build (no source maps), measured 2026-09-27 on Windows 11 (x64), Node 24.16.0, Next.js 16.3.6
(Turbopack), React 19.3.0. Dynamic routes are measured on their empty-state page.

| Route | initial | total | loaded |
| --- | --- | --- | --- |
| `/` | 138.2 kB | 138.2 kB | 147.5 kB |
| `/matrix` | 138.2 kB | 138.2 kB | 147.5 kB |
| `/trials/[cell]/[trial]` | 160.4 kB | 160.4 kB | 169.7 kB |
| `/lineage/[trial]/[thread]` | 140.0 kB | 198.1 kB | 207.4 kB |
| `/findings/[id]` | 138.2 kB | 138.2 kB | 147.5 kB |
| `/compare/[scenario]` | 138.2 kB | 138.2 kB | 147.5 kB |
| `/methodology` | 147.5 kB | 147.5 kB | 147.5 kB |

CI measured the same build on Linux (ubuntu-24.04, Node 24.21.0) byte for byte: the same sizes to the byte
on every route, and the same library table
([run 36350258591](https://github.com/s2002kumar/crashcourt/actions/runs/36350258591)).

The 9.3 kB between total and loaded on most routes is the methodology page's tab code, fetched after load
because every header links to that page.

The attribution below comes from a source-mapped build of the same code, whose routes measure about
0.1 kB smaller.

### The framework floor

On `/`, 129.6 kB of the 138.2 kB is Next.js itself, including the React it bundles. Within it, React DOM
alone is 64.0 kB, the RSC client 7.5 kB, and React 3.1 kB; most of the rest is the App Router (its segment
cache 16.0 kB, its reducers 10.8 kB). That is fixed for this stack; everything the site adds has to fit in
what is left of each budget.

### Library costs on real routes

| Library | Route | Loads | Own | With dependencies | Dependencies in the bundle |
| --- | --- | --- | --- | --- | --- |
| d3-scale | `/trials/[cell]/[trial]` | with the page | 1.1 kB | 9.2 kB | d3-array, d3-format, d3-interpolate, d3-color |
| d3-zoom | `/trials/[cell]/[trial]` | with the page | 3.3 kB | 16.8 kB | d3-selection, d3-transition, d3-drag, d3-dispatch, d3-interpolate, d3-color, d3-ease, d3-timer |
| d3-scale and d3-zoom together | `/trials/[cell]/[trial]` | with the page | 4.3 kB | 20.3 kB | the union of the two rows above |
| @xyflow/react | `/lineage/[trial]/[thread]` | lazily, after the page | 23.5 kB | 57.3 kB | @xyflow/system (15.8 kB), zustand, classcat, use-sync-external-store, and the d3-zoom set above |

Only `linear` scales are imported, so d3-time and d3-time-format are shaken out of d3-scale. React Flow
brings its own copy of the d3-zoom set on the lineage route, which is why that route loads it lazily: no
other page pays for it.

## Decisions the measurements drove

- **Radix per package, and only where the platform has no equivalent.** The first build imported the
  `radix-ui` package for a dialog and a toggle group in the header, and `/` measured 156.2 kB initial
  (source-mapped build), over the spec's 150 kB target. The keyboard list became a native `<dialog>` and
  the theme switch a native radio group, and tabs come from `@radix-ui/react-tabs`: `/` dropped to 138.1 kB
  on the same build and the tab code (9.3 kB) loads only on the methodology page.
- **React Flow is lazy** (`next/dynamic`, client only). It adds 58.1 kB to the lineage route after the page
  has rendered and nothing to any other route.
- **The timeline loads d3 with its page.** The failure explorer's main content is the timeline, so d3-scale
  and d3-zoom (20.3 kB with dependencies) load with the page instead of after it.

## Budgets

Each limit is the measured size plus 5%, rounded up to a whole kB, and never above the spec's target where
one exists (`/` initial 150 kB, lineage total 300 kB).

| Route | Checked | Limit | Spec target |
| --- | --- | --- | --- |
| `/` | initial | 146 kB | 150 kB |
| `/matrix` | initial | 146 kB | |
| `/trials/[cell]/[trial]` | initial | 169 kB | |
| `/lineage/[trial]/[thread]` | initial | 147 kB | |
| `/lineage/[trial]/[thread]` | total | 209 kB | 300 kB |
| `/findings/[id]` | initial | 146 kB | |
| `/compare/[scenario]` | initial | 146 kB | |
| `/methodology` | initial | 155 kB | |

Every measured route must have a budget, and every budget must name a measured route; size-limit refuses
to run otherwise. `npm run measure` prints the limit the rule proposes beside the committed one. To change a
limit, measure a release build again and record the new numbers here in the same commit.

## Reproduce

```bash
npm ci
npm run build && npm run measure        # route sizes and proposed limits (.budgets/measure.json)
npm run size                            # checks budgets.json
CRASHCOURT_SOURCEMAPS=1 npm run build   # source maps, for attribution only
npm run measure                         # adds the library table
```
