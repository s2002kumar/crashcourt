## The twelve items

1. **Engine and result model.** `check_trial(artifacts, registry, registry_sha256)` returns schema v1's
   `ResultRecord` and a `CheckerReport` (`checker.json`). Records serialize canonically (sorted keys); two
   runs, and runs with the histories in another order or with every `mono_ns` scrambled, give the same bytes.
2. **Predicates separate from classification.** Layer A returns ANOMALY, NO_ANOMALY, or NOT_EXERCISED with
   evidence pointers and named witnesses; it never names an outcome or a clause. Layer B reads only those.
3. **Unexercised invariants are omitted.** They are listed in `checker.json` under `not_exercised` with the
   missing witness. When nothing is exercised there is no `result.json` (schema v1 needs one outcome).
4. **Fault not fired is INVALID.** Every arm needs exactly one `fp.hit` with the declared action (trigger 10),
   every hit must sit at its declared landmark (11), and every declared fault must show the symptoms of its
   row in 3.6 (12): pause, SIGKILL, exit, SIGSTOP/SIGCONT, lost ack, reset, delayed ack, backend termination,
   database restart, redelivery, second resume.
5. **I3 is a harness alarm.** The head state claiming an effect the ledger lacks, or a `client.ok` run whose
   effect-model path has no ledger row, is INVALID trigger 15 and never an outcome (decision 4; AM5).
6. **Clause polarity from the registry, grades from the mapping.** `mapping.py` grades each use (G3, G2, G1,
   P) and states its durability condition; `classify.py` takes polarity, `applies_to`, and the version scope
   from the registry at classification time.
7. **Describes clauses never carry PASS.** PASS needs polarity `guarantees` and grade G3 or G2 (with the
   caveat in `reason`). The property test reassigns polarities at random and checks it (decision 1).
8. **EXPECTED only with every condition witnessed.** A permission with an unwitnessed condition falls through
   to GAP or a candidate.
9. **VIOLATION_CANDIDATE requirements.** A guaranteeing clause in scope that forbids the anomaly, no permission
   witnessed, the thread not disclaimed, fault verification passed, no harness-originated event on the thread.
   The checker never writes VIOLATION, and no checker file names it (static test).
10. **Synthetic tests** for I1a, I1b, I2, I3, I4, I5a-c, I6a-b, I7a-c, I8, I11, on W1 (approve, reject,
    misuse), W5, a forced fork, a kill mid-execute with redelivery, kills at execute's `put_writes` before and
    after, LG-PW's exception case, a SIGSTOP-and-redeliver fork, a loss before the first checkpoint, network
    and database faults, and a double resume.
11. **Mutation tests.** AM1-AM10 each give the named outcome (AM7 is built as a synthetic trial: a re-run on a
    replacement worker cannot be made by editing a fault-free trial consistently). Each predicate also has a
    mutant that makes it report ANOMALY.
12. **Freeze plumbing.** `freeze.compute` hashes every checker file, the registry, each effect model, and each
    landmark table; `render`, `parse`, and `verify` give the `FROZEN.md` round trip the freeze commit will use.
    A test fails if `FROZEN.md` exists while the state is PRE-FREEZE. `checker.json` carries the version, the
    freeze state, `authorized_for_new_evidence: false`, the checker, registry, effect-model, and landmark
    hashes, and a null `frozen_sha256`.

## Contradiction found (stop and decide before the freeze)

**"Running at a stop" (2.0) cannot witness I4(a) at landmark L-EXW, so K1a / C11-8039 cannot give its
predicted EXPECTED.** 2.0: "Running at a stop: a node with `node.start` and no `node.end` in that process
before the stop's seq." I4(a) and I7a's permission need "a stop while the producing node was running". 4.2
defines L-EXW as "after `node.end execute`", and K1a kills at L-EXW's `put_writes.before`. LangGraph writes a
task's writes only after its node function returns: `pregel/_runner.py:574` (`commit`), whose success branch
calls `put_writes` at `:613` (langgraph 1.2.12, the pinned version). A workload's `node.end` is written inside
the node, so it always precedes the task's `put_writes`. At K1a's kill execute is therefore not running by
2.0's definition, (a) cannot hold, and the duplicate falls to (e): GAP "duplicate with no documented cause"
(and I7a GAP). K1a predicts I4 EXPECTED (a) and I7a EXPECTED, and C11-8039 must match its published outcome
in 19 of 20 or the batch's control fails. Pinned by
`test_checker_readings.py::test_contradiction_running_at_a_stop_and_the_c11_8039_shape`. I implemented 2.0 as
written and did not change it. A kill before `node.end` (AM7's shape) gives EXPECTED (a) as specified.

## Review

A review against the specification, before this record was written, found two blockers
and four major problems; all are fixed, each with a regression test (`test_checker_regressions.py`):

- A network fault that never touched its call verified, so a delayed-ack cell could read PASS: now R20.
- I1a paired a put whose acknowledgment was lost with a node start in a later run, a false candidate: pairs
  are now within one run, and a run that continues after its put failed is still an anomaly.
- Trigger 6 excused any failed effect response of a worker that later died; a non-zero exit counted as a
  stop; undeclared faults fed the stop witnesses: now R21-R23.
- I7a gave EXPECTED on a disclaimed thread: now R24.
- After the freeze, a trial without the frozen landmark table raised: verification is now per trial (R25).
- The SIGSTOP silence check cannot fire with schema v1's edges: recorded as R19, not claimed as verified.
- R7 had departed from 2.3's "I4 PASS (no duplicates)"; it now implements the text, and the vacuity concern
  is a question for the audit.

Smaller fixes: the manifest copy is hashed (trigger 13); sink readings need the batch's source hash; a
redelivery's read must follow the redelivery in that op; node events must carry `task_id` and `data.node`, and
a `node.end` must close a started run; a dispatched worker with an empty history must still exit before the
snapshot; I2 counts any start of the task not before its commit as a re-run.

## What the checker reads that T-07 and T-09 must write

- Node events: `task_id` (T-09 card) and the node name in `data.node`, which the T-09 card does not name yet.
- `worker.exit`: `data.proc`, and `data.signal` or a negative `data.returncode`. `fault.inject`: the target as
  `data.proc`, `data.worker`, or `data.pid`; the kind as `data.signal` or `data.fault` (T-05's names).
- `client.ok` / `client.fail` with `data.worker` and `data.worker_seq` (T-04's result edge).
- The proxy-to-worker map in the scenario facts (3.5), and toxic injects with T-05's `proxy`, `toxic`, and
  `stream` fields.
- Snapshot metadata: the orchestrator seq it was taken after, the DSN, the SHOW values, the postmaster start,
  the installed toxics, the threads covered; two snapshots and the pre-trial emptiness counts.
- The worker's failpoint registry `failed` set at shutdown; sink `/health` readings; the ledger export and the
  sink's own `/ledger/verify` answer.
