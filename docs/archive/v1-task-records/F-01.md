## Decisions
1. **Stack and pins.** Next.js 16.3.6 with Turbopack, React 19.3.0, TypeScript 7.0.2, Tailwind 4.3.3,
   `@radix-ui/react-tabs` 1.1.21, d3-scale 4.0.2, d3-zoom 3.0.0, d3-selection 3.0.0, `@xyflow/react` 12.12.0, Ajv
   8.20.0, json-schema-to-typescript 16.0.0; exact versions and a committed `package-lock.json` (npm, which
   ships with Node; `npm ci` in CI). Node 24: CI uses 24.21.0 (`site/.node-version`); `engines` allows
   24.16 and later. TypeScript 7 has no JavaScript compiler API, but Next 16.3 type-checks through the `tsc`
   command by default (`experimental.useTypeScriptCli`), so the native compiler works for both the build and
   `npm run typecheck`.
2. **How the build keeps verdicts out of the UI.** Apart from the two schema modules generated from `schemas/v1`,
   `lib/tokens.ts` is the only source file that spells a verdict name, holds the list of verdicts, or names the
   `Verdict` type; it maps a verdict to its glyph, label, and color and offers `verdictLegend()` for the
   vocabulary and `VerdictProp` for components that render a verdict they were given.
   `scripts/guard-verdicts.ts` runs before every build and in CI and reads every source file under `site/`
   (`.ts`, `.tsx`, `.mts`, `.cts`, `.js`, `.jsx`, `.mjs`, `.cjs`, `.json`, `.css`) except the top-level tests, build
   output, and fixtures, and the two generated modules (which `check:schema` keeps equal to `schemas/v1`). It
   fails on a quoted outcome name (the five verdicts, and the two outcomes that are not verdicts, which must never
   be turned into one), the list, the word `Verdict`, or indexing into the legend or `VerdictProp`. It reads text,
   so it cannot see a name built at run time, a verdict picked from the legend by its token, or one derived at
   the type level; it is a tripwire that review backs up, not a proof, and its header says so. Tokens for the two
   outcomes that are not verdicts come with the pages that render results (F-02).
3. **Empty-state pages for dynamic routes.** A static export must produce at least one page per dynamic
   route (Next 16.3 fails with "returned an empty array from generateStaticParams()"). Until artifacts
   exist, each dynamic route exports one page at the segment `none`, which says there is nothing to show
   and is marked `noindex`. The pages pass no ids yet; F-02 passes the ids it reads from validated artifacts.
   `/compare` stays unlinked, as the card's "hidden until two targets exist" requires.
4. **Budget first, then components.** The first build measured `/` at 156.2 kB initial (source-mapped), over
   150 kB, with the `radix-ui` package providing a dialog and a toggle group in the header. The keyboard list
   is now a native modal `<dialog>` (focus containment, Escape, and focus return from the browser) and the
   theme switch a native radio group; tabs come from `@radix-ui/react-tabs`. `/` is 138.2 kB in a release
   build. Next.js with its React is 129.6 kB of that, so the site has about 20 kB to work with on every page.
5. **Budget measurement.** `scripts/measure-bundles.ts` records per route the HTML's scripts (initial), the
   route's own total with the router's prefetch blocked, and everything loaded. Library cost comes from
   source maps grouped by package, with each library's dependency closure. Limits are the measurement plus
   5%, rounded up, and never above the spec's target. size-limit checks them in CI.
6. **Lighthouse without `@lhci/cli`.** Its latest release (0.15.1) pins Lighthouse 12.6.1 and brought 10 npm
   advisories (7 high) through puppeteer-core, extract-zip, and tmp. `scripts/lighthouse.ts` runs Lighthouse
   13.5.0 (no advisories) and asserts the targets: performance at least 90 on `/` (median of three) and
   accessibility 100 on every route the browser tests visit (one shared list), the hidden `/compare` stub
   included. It launches the Chromium that
   `npx playwright install chromium` installs for the pinned `@playwright/test`, not whatever Chrome the machine
   has.
7. **Exact clocks.** `wall_ns` is about 1.8e18, beyond `Number.MAX_SAFE_INTEGER`. The loader validates each
   line with Ajv, then parses it again with a reviver that reads the source text, so `mono_ns` and `wall_ns`
   are exact `bigint`s (and any other integer past 2^53). A clock written in exponent form is refused.
8. **Artifacts the site reads.** `CRASHCOURT_ARTIFACTS`, else `site/fixtures` if it exists; nothing yet.
   Every file must be a `manifest.json`, `batch.json`, `result.json`, or `.jsonl` history, and all failures are
   reported together. Batch and result records carry `provenance`, which the release guard (F-02) reads. The
   v1 record schemas carry what each outcome needs and the `DEMO-` rule, so Ajv rejects what the harness's models
   reject; the site adds the one rule JSON Schema cannot express, one outcome per invariant. That a result's
   manifest hash matches its batch's is a cross-file check for the release guard. The shared cases in
   tests/data/records-v1.json keep the site and the models in agreement. A review date must be a real day, years
   below 100 included.
9. **Colors are tested, not asserted.** `tests/unit/tokens.test.ts` parses `tokens.css` and checks WCAG
   contrast and CIEDE2000 separation under simulated dichromacy (Machado et al. 2009) in both themes. axe
   found a case it did not cover: verdict-colored badge text fell under 4.5:1 on its own tint. Badge labels
   are now in ink, and the token test checks that case too.
10. **Fonts from the lockfile.** Instrument Sans and JetBrains Mono (both OFL) come from Fontsource packages
    through `next/font/local`, so a build never fetches from Google.
11. **A Next.js bug on Windows.** Next 16.3.6 writes the router's segment prefetch files with a Windows path
    separator (`export/index.js`, `collectSegmentPaths` uses `path.relative`), so on Windows every prefetch
    404s. `scripts/postbuild.ts` renames them; on Linux, where CI and releases build, it finds nothing to do.
    It is filed upstream as vercel/next.js#85374 (vercel/next.js#92339 was closed as its duplicate), with a fix
    open in vercel/next.js#99058; the script says to delete it once a release carries the fix.
12. **Axis labels.** The timeline's tick labels come from the scale over the trial's time span. They label an
    axis and are not artifact values; I read the rule that the site shows only artifact values as covering data
    values, not axis labels. F-04 is the place to confirm that.
13. **Which manifests the site validates.** T-01's reference manifest was recorded before the clause registry
    existed, so it lacks `clause_registry_sha256`, which v1 requires. It stays as the record of T-01's environment,
    and the site's test reads the references recorded under v1.
