## Decisions
1. **The delayed acknowledgment uses a long `latency` toxic.**
   - Measured, and read in Toxiproxy's source: a `timeout` toxic with timeout=0 discards what it reads, and removing it
     closes the connection. The plan had assumed it holds responses until they are released.
   - So `drop_responses` (the `timeout` drop) is the lost acknowledgment, and `hold_responses` (a 24-hour downstream
     latency) is the deterministic delayed one: removing it forwards the held data.
   - A schedule therefore picks the outcome when it adds the toxic. Details: research/fault-selftest.md. I noted the
     correction on #5.
2. **Holds must be alone.** A new toxic on the held stream releases a latency hold at once; a toxic on the other stream
   does not. `hold_responses` refuses a proxy that has toxics, and the other fault functions refuse to add a toxic while
   a hold is active. The self-test checks both halves.
3. **Bookkeeping.** `fault.inject` is written before the fault is applied. Every inject gets exactly one `fault.heal`:
   when healed, at once for instantaneous faults (kill, termination, restart), or when applying or healing failed. The
   heal carries what the fault observed: an exit status, how many backends ended, how long a restart took. A failed
   inject or heal has status `fail` and the error in the envelope's `error` field, and raises `FaultError`, so the
   trial is INVALID.
4. **A fault that did nothing is an error.**
   - `terminate_backends` waits up to five seconds for each backend to exit (with no timeout, `pg_terminate_backend`
     returns true once the signal is sent), counts only the ones that exited, and raises when none did.
   - `kill` raises when the process exited some other way before the SIGKILL reached it.
5. **Safety.**
   - `ToxiproxyClient` refuses a non-loopback API URL, and the self-test refuses database DSNs whose hosts are not
     loopback addresses or socket directories.
   - `ensure_proxy` never replaces an existing proxy, which would drop live connections, and fails if its upstream is
     not the target database.
   - `restart_database` checks the container's `com.docker.compose.project` label.
   - `terminate_backends` needs an explicit application_name and skips its own backend.
6. **The self-test reports what it did not check.** A primitive that raises fails its check with the error instead of
   ending the run, and the headline names skipped checks (signals on Windows) and checks not run (the restart, under
   `--no-restart`).
7. **Signals need POSIX.** On Windows the signal functions raise, and the self-test reports `skip` for that check. On
   Linux a skip would fail the integration test.
8. **Per-worker targeting is T-07's.** A toxic applies to every connection through its proxy, so with one proxy any
   network fault in a two-worker schedule would hit both workers. T-07 (#17) gives each worker its own proxy and port.

## Review fixes
The review of 08716f8 (2026-10-08) asked for four changes and five smaller ones:

1. **Instant faults lost what they observed.** The observation is in `fault.heal` (decision 3), and a termination that
   ends no backend raises (decision 4).
2. **`add_latency` had no check.** The self-test adds 200 ms on the downstream and requires the client to wait at least
   that long and the row to commit.
3. **The wrong assumption, in plain words.** research/fault-selftest.md and my comment on #5 now say what the plan
   assumed and what the toxic does, without quoting; the Toxiproxy citations stay. "The first half holds" is gone, as
   the toxic drops the data. The record no longer says the fault semantics are unchanged (deviations, decision 1).
4. **Per-worker proxies** are T-07's, which #17 already says (decision 8).

Smaller: failed heals use the envelope's status and error; the termination count includes only true results; the
headline shows skipped and omitted checks; the self-test DSNs get the loopback rule; "checks" rather than "proves".

Also fixed: `pg_terminate_backend` returned true once its signal was sent, so the count could include a backend that had
not exited; each call now waits for the exit (decision 4). A SIGKILL whose target had already exited is an error. The
docstrings name faults by what they do rather than by identifiers from a document outside the repository.
